1. What is a Signal?

A signal is a reactive value holder — a "smart variable" that announces when it changes, so Angular knows exactly what to update.

The problem it solves

  • Old way (Zone.js): Angular watched the entire app and guessed what changed on every event — like a guard checking every room when anyone moves. Broad and wasteful.
  • Signals way: the signal tells Angular exactly what changed and exactly which part of the screen depends on it. Precise and fast.
import { signal } from '@angular/core';

count = signal(0); // 0 is the initial value
🧠 AnalogyA signal is a live "smart variable": a normal variable just holds a value; a signal also raises its hand and says "I changed!"

2. Reactivity (the big idea)

Reactivity = values that update themselves when their inputs change.

// Non-reactive: a frozen snapshot
let a = 2;
let b = a * 2;   // b is 4
a = 5;           // b is STILL 4 — it doesn't care

// Reactive: a live mirror
a = signal(2);
b = computed(() => a() * 2);  // b is 4
a.set(5);                    // b is NOW 10, automatically
🧠 AnalogyA normal variable is a photo (frozen). A reactive value is a live mirror (always current). You describe relationships once; the system keeps everything in sync forever.

3. Reading a Signal

A signal is a function. To read its value, you call it with parentheses.

count()   // ✅ reads the value → 0
count     // ❌ this is the signal itself, not the value

In the template:

{{ count() }}   // ✅ shows 0
{{ count }}     // ❌ prints the function object
Why it mattersCalling the signal tells Angular "I'm reading you right now" — that's how it registers this exact spot as a dependency and knows to update it later. Reading always needs (), in templates and TypeScript alike.

4. Updating: set vs update

MethodUse whenExample
.set(value)The new value does not depend on the old onecount.set(0)
.update(fn)The new value is derived from the old onecount.update(c => c + 1)
⚠️ Never reassignDon't do count = 5. That destroys the signal and replaces it with a plain number. Always go through .set() or .update().
🧠 Analogy.set() = "forget what you had, here's the new value." .update() = "take what you've got and transform it."

5. Computed Signals — computed()

Creates a derived, read-only signal that recalculates automatically when its dependencies change.

import { computed } from '@angular/core';

doubleCount = computed(() => this.count() * 2);
  • Read-only: no .set() / .update() — it's derived, not owned. Trying to set it is a compile error.
  • Lazy + cached: only recomputes when a dependency actually changes; otherwise returns the cached result.
  • Auto-tracked: reading this.count() inside registers count as a dependency.
🧠 AnalogyLike a spreadsheet formula cell: B1 = A1 * 2. Change A1 and B1 updates itself. You never edit B1 directly.

6. Effects — effect()

Runs a side effect (logging, saving to storage, syncing) whenever a signal it reads changes.

import { effect } from '@angular/core';

constructor() {
  effect(() => {
    console.log('Count is now:', this.count());
  });
}
  • Runs once immediately to establish dependencies, then re-runs on every change.
  • Must be created in an injection context (the constructor is one; ngOnInit is not).
⚠️ Golden rule: never write to a signal inside an effectThe effect reads the signal (dependency) and writing to it re-triggers the effect → infinite loop. It's like a mic picking up its own speaker — feedback screech. For derived values, use computed() instead.

7. Signals holding Arrays / Objects

Golden ruleNever mutate the existing array/object. Always create a new one. A signal only fires when it gets a new reference — mutating in place looks like "no change."
toggleTodo(id: number) {
  this.todos.update(list =>
    list.map(todo =>
      todo.id === id ? { ...todo, done: !todo.done } : todo
    )
  );
}
  • .map() returns a brand-new array (never mutates the original).
  • { ...todo, done: !todo.done } builds a new object with one field changed.
  • Unmatched items are returned unchanged.
🧠 AnalogyA signal notices when you hand it a different box, not when you quietly rearrange the contents of the box it already has.

8. Getter vs computed()

A plain getter get itemsLeft() { return ... } works visually, but computed() is better:

Gettercomputed()
RunsEvery change-detection cycleOnly when a dependency changes
CachingNone — recomputes alwaysLazy + cached
ComposableNo (invisible to signals)Yes (feed into other computed/effect)
Zoneless-readyRiskyYes — drives change detection
Rule of thumbTrivial + used once → inline/getter is fine. Reused or non-trivial → name it with computed().

9. Common Gotchas (debugged in the lesson)

① effect() in ngOnInit throws

NG0203: effect() can only be used within an injection context. The injection context is only "open" during the constructor. Move effects into the constructor (or pass an Injector as an advanced escape hatch).

② Theme didn't persist — effect timing

Loading saved state in ngOnInit failed because the save-effect runs immediately in the constructor and overwrote storage with the default before ngOnInit read it. Fix: restore state before the effect runs — ideally right in the signal's initializer.

// ✅ Born with the saved value, so the effect saves the right thing
theme = signal<'light' | 'dark'>(
  (localStorage.getItem('theme') as 'light' | 'dark') || 'light'
);

③ @for error on Angular 16

The @for control-flow block needs Angular 17+. On v16 use the classic *ngFor:

<p *ngFor="let todo of todos()">{{ todo.title }}</p>

④ Mutating an array signal

Pushing into the same array won't trigger updates — create a new array (see §7).

10. Signals vs RxJS

Rule of thumb

Signals for local/synchronous UI state. RxJS for async streams & events over time.

SignalsRxJS (Observables)
Best forComponent/UI state, derived valuesHTTP, websockets, debounced search, event streams
NatureSynchronous value (always has a current value)Async stream over time (may emit 0..∞)
ReadCall it: count()Subscribe / async pipe
OperatorsFew (set/update/computed/effect)Hundreds (map, filter, debounceTime, switchMap…)
CleanupAutomaticMust unsubscribe (or use async pipe / takeUntilDestroyed)
BridgeAngular offers toSignal() and toObservable() (from @angular/core/rxjs-interop) to convert between the two when you need both worlds.

11. Full Feature Code (Todo + Theme)

Everything wired together: writable signals, computed, effect, immutability, and persistence.

app.component.ts

import { Component, computed, signal, effect } from '@angular/core';

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html',
  styleUrls: ['./app.component.scss']
})
export class AppComponent {
  // born with the saved theme so the effect won't clobber it
  theme = signal<'light' | 'dark'>(
    (localStorage.getItem('theme') as 'light' | 'dark') || 'light'
  );
  themeClass = computed(() => this.theme() === 'light' ? 'light-theme' : 'dark-theme');

  todos = signal([
    { id: 1, title: 'Learn signals', done: false },
    { id: 2, title: 'Learn computed', done: false },
    { id: 3, title: 'Learn effects', done: false },
  ]);
  itemsLeft = computed(() => this.todos().filter(t => !t.done).length);

  constructor() {
    effect(() => localStorage.setItem('theme', this.theme()));
  }

  toggleTodo(id: number) {
    this.todos.update(list =>
      list.map(t => t.id === id ? { ...t, done: !t.done } : t));
  }
  toggleTheme() {
    this.theme.update(t => t === 'light' ? 'dark' : 'light');
  }
}

app.component.html

<div [class]="themeClass()">
  <p *ngFor="let todo of todos()" (click)="toggleTodo(todo.id)">
    {{ todo.title }} — {{ todo.done }}
  </p>
  <p>{{ itemsLeft() }} items left</p>
  <button (click)="toggleTheme()">Toggle theme</button>
</div>

app.component.scss

.light-theme { background-color: #fff; color: #000; }
.dark-theme  { background-color: #000; color: #fff; }

12. Interview Q&A

Q: What is a signal and why did Angular introduce them?

A signal is a reactive wrapper around a value that notifies consumers when it changes. They give Angular fine-grained reactivity — updating only what actually depends on the changed value — reducing reliance on Zone.js and enabling future zoneless change detection.

Q: Why do you call a signal with parentheses?

Signals are functions. Calling count() reads the current value and registers the caller as a dependency, so the framework knows to re-run that consumer when the value changes.

Q: Difference between set and update?

set(v) replaces the value outright. update(fn) computes the new value from the current one. Use update for increments/toggles where the new value depends on the old.

Q: What is a computed signal? Is it cached?

A read-only signal derived from other signals. It's lazy (computes only when read) and cached (re-runs only when a tracked dependency changes). You can't write to it.

Q: What is an effect and what's the #1 rule?

An effect runs a side effect whenever a signal it reads changes. Never write to a signal inside an effect — it causes an infinite loop. Use computed() for derived state instead.

Q: Why does effect() fail in ngOnInit?

Effects must be created in an injection context, which is active during the constructor but not in ngOnInit. Create effects in the constructor, or pass an explicit Injector.

Q: How do you update a signal that holds an array or object?

Immutably — return a new array/object (e.g. via map/spread). Signals detect change by reference, so mutating in place won't trigger updates.

Q: Signals vs RxJS — when do you use each?

Signals for synchronous local UI state and derived values; RxJS for asynchronous streams (HTTP, websockets, debounced input). Bridge with toSignal() / toObservable().

Q: Getter vs computed for derived values?

A getter recomputes on every change-detection cycle and isn't reactive/composable. computed() is lazy, cached, composable, and zoneless-ready — preferred for anything non-trivial or reused.

Q: Are computed signals writable?

No. computed() returns a read-only Signal (no set/update). Attempting to write is a TypeScript compile error.

13. Cheat Sheet

// create
count = signal(0);
name  = signal<string>('Nihal');

// read (always with parens)
count();

// write
count.set(5);
count.update(c => c + 1);

// derive (read-only, lazy, cached)
double = computed(() => count() * 2);

// side effect (constructor only; never write a signal here)
effect(() => console.log(count()));

// arrays/objects → new reference
items.update(list => [...list, newItem]);

14. Signal Inputs — input() Angular 17.1+

The modern replacement for the @Input() decorator. A component input that is a signal — read it with (), and it integrates with computed/effect automatically.

import { Component, input } from '@angular/core';

@Component({ selector: 'user-card', /* ... */ })
export class UserCardComponent {
  // optional input, default undefined
  name = input<string>();

  // optional with a default value
  role = input('guest');

  // REQUIRED input — caller must provide it
  userId = input.required<number>();

  // derived from an input — fully reactive
  greeting = computed(() => `Hello, ${this.name()}`);
}

Used by the parent exactly like before:

<user-card [name]="'Nihal'" [userId]="42" />

Transforms & aliases

// transform: coerce/clean the incoming value
disabled = input(false, { transform: booleanAttribute });
// alias: external name differs from the property name
value = input(0, { alias: 'count' });
@Input() vs input()
@Input() decoratorinput() function
TypePlain propertyRead-only signal
Readthis.namethis.name()
ReactiveNeeds ngOnChangesWorks in computed/effect natively
Required@Input({ required: true })input.required()
⚠️ Read-onlySignal inputs are read-only — you can't .set() them. The value flows in from the parent. (For writable, see model() below.)

15. Two-way Binding — model() Angular 17.2+

A writable signal input that supports two-way binding with the [(...)] "banana-in-a-box" syntax. The child can change it and notify the parent.

import { Component, model } from '@angular/core';

@Component({ selector: 'toggle-switch', /* ... */ })
export class ToggleSwitch {
  checked = model(false); // writable AND two-way bindable

  toggle() {
    this.checked.update(v => !v); // updates child + emits to parent
  }
}

Parent binds both directions at once:

<toggle-switch [(checked)]="isOn" />
How it worksmodel('x') is sugar for an input named x plus an output named xChange — the exact convention Angular's two-way binding looks for.

16. Outputs — output() Angular 17.3+

The function-based replacement for @Output() + EventEmitter. Cleaner, fully typed. (Note: outputs are not signals — they're event emitters — but they're part of the same modern API family.)

import { Component, output } from '@angular/core';

export class SearchBox {
  search = output<string>(); // typed event

  onType(text: string) {
    this.search.emit(text); // fire the event
  }
}
<search-box (search)="handleSearch($event)" />
vs @Output()No need to instantiate new EventEmitter(); output() returns an OutputEmitterRef with a clean .emit() API and better type inference.

17. Signal Queries — viewChild() / contentChild() Angular 17.2+

Signal versions of @ViewChild / @ContentChild. The query result is a signal — no more "undefined until ngAfterViewInit" surprises; you just read it reactively.

import { Component, viewChild, viewChildren, ElementRef } from '@angular/core';

export class Form {
  // single element (signal, may be undefined until rendered)
  nameInput = viewChild<ElementRef>('nameInput');

  // required → never undefined once view is ready
  submitBtn = viewChild.required<ElementRef>('submitBtn');

  // multiple elements → signal of a readonly array
  items = viewChildren<ElementRef>('item');

  focusName() {
    this.nameInput()?.nativeElement.focus();
  }
}
Why it's betterBecause it's a signal, you can react to query results in a computed or effect instead of relying on lifecycle hooks like ngAfterViewInit.

18. untracked() Angular 16+

Reads a signal without registering it as a dependency. Use it inside an effect/computed when you want the current value but don't want changes to that signal to trigger a re-run.

import { effect, untracked } from '@angular/core';

effect(() => {
  // re-runs ONLY when userId changes...
  const id = this.userId();
  // ...reads currentTab WITHOUT depending on it
  const tab = untracked(() => this.currentTab());
  this.analytics.log(id, tab);
});
Mental modelInside a reactive context, every signal you call becomes a dependency. untracked() is the opt-out — "let me peek at this value without subscribing to it."

19. Effect Cleanup — onCleanup Angular 16+

An effect can register a cleanup callback that runs before the next run and when the effect is destroyed. Essential for timers, subscriptions, or listeners so you don't leak.

effect((onCleanup) => {
  const id = this.activeId();
  const timer = setInterval(() => poll(id), 1000);

  onCleanup(() => clearInterval(timer)); // tidy up before re-run / on destroy
});
RememberEffects created in an injection context are auto-destroyed with their component. onCleanup handles the resources inside the effect, not the effect itself.

20. Equality Functions Angular 16+

By default signals use Object.is to decide if the value "changed." You can supply a custom equal function to skip notifications for values you consider equivalent.

// won't fire if the new object is deep-equal to the old
user = signal(initialUser, { equal: _.isEqual });

// also available on computed
total = computed(() => expensive(), { equal: (a, b) => a === b });
WhyPrevents needless recomputations/re-renders when a "new" value is logically the same. Default Object.is means a new array/object reference always counts as changed (hence the immutability rule).

21. linkedSignal() Angular 19+

A writable signal that also resets/derives from a source — think "a computed you're allowed to override." Perfect for state that should follow a source but still be locally editable.

import { linkedSignal } from '@angular/core';

// selectedOption resets whenever the options list changes,
// but the user can still pick a different one in between
selected = linkedSignal(() => this.options()[0]);

choose(opt: Option) {
  this.selected.set(opt); // writable, unlike computed
}

Advanced form with explicit source + computation:

selected = linkedSignal({
  source: () => this.options(),
  computation: (opts, prev) =>
    opts.includes(prev?.value) ? prev!.value : opts[0],
});
computed vs linkedSignalcomputed = read-only, always reflects the formula. linkedSignal = derives a default but you can write to it, and it re-derives when the source changes.

22. resource() / rxResource() Angular 19+

Loads async data into signals. It tracks a reactive request, runs a loader, and exposes value, status, error, and isLoading as signals — no manual subscriptions.

import { resource } from '@angular/core';

userId = signal(1);

userResource = resource({
  // re-fetches automatically whenever request() changes
  request: () => ({ id: this.userId() }),
  loader: async ({ request, abortSignal }) => {
    const res = await fetch(`/api/users/${request.id}`, { signal: abortSignal });
    return res.json();
  },
});

// in template:
// @if (userResource.isLoading()) { Loading... }
// @else { {{ userResource.value()?.name }} }
rxResource()Same idea but the loader returns an Observable instead of a Promise — use it when you already have RxJS-based services (e.g. HttpClient).
StatusExposes a status() signal: idle, loading, resolved, error, etc. — great for driving UI states declaratively.

23. RxJS Interop — toSignal() / toObservable() Angular 16+

Bridge the two reactivity worlds. From @angular/core/rxjs-interop.

import { toSignal, toObservable } from '@angular/core/rxjs-interop';

// Observable → Signal (auto-unsubscribes on destroy)
data = toSignal(this.http.get('/api/data'), { initialValue: [] });

// Signal → Observable (e.g. to use debounceTime, switchMap)
query$ = toObservable(this.query);
results$ = this.query$.pipe(
  debounceTime(300),
  switchMap(q => this.api.search(q))
);
When to bridgeUse toSignal() to consume async data as a signal in templates; use toObservable() when you need RxJS operators (debounce, retry, combineLatest) on signal-driven values.

24. Advanced Interview Q&A

Q: How do signal inputs differ from @Input()?

Signal inputs (input()) are read-only signals read with (), are reactive in computed/effect without ngOnChanges, and support input.required(), transform, and alias options. @Input() is a plain property needing lifecycle hooks to react.

Q: What is model() and when do you use it?

A writable signal input enabling two-way binding [(x)]. Internally it's an input x plus an output xChange. Use it for reusable form controls / toggles where the child both reads and writes a value the parent owns.

Q: What problem does untracked() solve?

It reads a signal's current value without creating a dependency, so changes to it won't re-trigger the surrounding effect/computed. Prevents unwanted re-runs when you only need a snapshot of a value.

Q: computed() vs linkedSignal()?

computed is read-only and always equals its formula. linkedSignal derives an initial/default value from a source but is writable, and re-derives when the source changes — ideal for "selected item resets when the list changes, but the user can still pick another."

Q: How does resource() handle race conditions?

It tracks the reactive request(); when it changes, the previous load is aborted via the provided abortSignal and a new one starts — so stale responses don't overwrite fresh ones. Status/value/error are all signals.

Q: How do you prevent memory leaks with effects?

Effects in an injection context auto-destroy with the component. For resources inside the effect (timers, listeners, subscriptions), register an onCleanup callback that runs before each re-run and on destroy.

Q: When would you bridge signals and RxJS?

Use toSignal() to render async streams (e.g. HTTP) as signals in templates with auto-unsubscribe. Use toObservable() when you need RxJS operators (debounceTime, switchMap, retry) on a signal-driven value like a search box.

Q: Why supply a custom equal function?

The default Object.is treats every new object/array reference as a change. A custom equal (e.g. deep equality) suppresses notifications when the value is logically unchanged, avoiding wasteful recomputation/re-render.
