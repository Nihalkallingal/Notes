2. NumPy

Concept: Fast numeric arrays. Instead of looping, you operate on whole arrays at once (vectorization). Broadcasting stretches smaller arrays to match shapes automatically.
Analogy: A spreadsheet where "multiply this whole column by 2" happens instantly, not cell-by-cell.
import numpy as np

a = np.array([[1, 2, 3], [4, 5, 6]])
print(a.shape)          # (2, 3)
print(a * 2)            # vectorized — every element doubled
print(a.mean(axis=0))    # reduction — column means

# Boolean masking: keep only values > 3
print(a[a > 3])          # [4 5 6]

# Broadcasting: add a row vector to every row
print(a + np.array([10, 20, 30]))

5. First Model — Logistic Regression supervised learning

Concept: Supervised learning = learn from labeled examples. Split features (X) from the label (y), split data into train/test (learn on one, judge on the other), fit, predict, evaluate.
Analogy: Study past exams (train), then take a fresh exam (test) to prove you learned the pattern, not memorized answers.
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, confusion_matrix

X = df[["Pclass", "Sex", "Age"]]   # Sex encoded 0/1 via .map
y = df["Survived"]

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2)
model = LogisticRegression().fit(X_train, y_train)
preds = model.predict(X_test)

print(accuracy_score(y_test, preds))   # ~80% vs ~62% baseline
print(model.coef_)                    # Sex = biggest driver
Quiz: why split into train/test?

To measure whether the model generalizes to unseen data instead of just memorizing the training set. High train + low test score = overfitting.

6. Trees & Ensembles

Concept: A decision tree asks yes/no questions to split data. Alone it overfits (memorizes) — fix with max_depth. A Random Forest averages many trees (ensemble voting) for a more robust model. Cross-validation gives a trustworthy score by testing on 5 different splits.
Analogy: One doctor can be wrong; a panel of 100 doctors voting (forest) is more reliable.
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import cross_val_score

rf = RandomForestClassifier(n_estimators=100, max_depth=5)
scores = cross_val_score(rf, X, y, cv=5)      # 5-fold CV
print(scores.mean(), scores.std())         # mean ± spread

rf.fit(X, y)
print(rf.feature_importances_)             # which features mattered

7. Feature Engineering & Encoding

Concept: Better inputs beat fancier models. Create new signal (e.g. FamilySize, IsAlone), extract info from text (Title from a name), and encode categories. Use one-hot for unordered categories so the model doesn't invent a fake order.
# New engineered features
df["FamilySize"] = df["SibSp"] + df["Parch"] + 1
df["IsAlone"] = (df["FamilySize"] == 1).astype(int)

# Extract title from name via regex
df["Title"] = df["Name"].str.extract(r" ([A-Za-z]+)\.")

# One-hot encode unordered categories
df = pd.get_dummies(df, columns=["Embarked", "Title"])

8. Hyperparameter Tuning classical ML complete

Concept: Models have dials (hyperparameters) you set before training. GridSearchCV tries every combination with cross-validation and reports the best. Tune on train only, then confirm on the held-out test set.
from sklearn.model_selection import GridSearchCV

param_grid = {"n_estimators": [100, 200], "max_depth": [4, 6, 8]}
grid = GridSearchCV(RandomForestClassifier(), param_grid, cv=5, n_jobs=-1)
grid.fit(X_train, y_train)

print(grid.best_params_)      # winning combo
print(grid.best_score_)       # CV score — should ≈ test score

9. Neural Networks with PyTorch deep learning

Concept: A neural net stacks layers of neurons that learn patterns. You scale features first (NNs are scale-sensitive), define the network, then hand-write the training loop: forward → loss → zero_grad → backward → step, repeated over epochs.
Analogy: Learning to shoot a basketball — shoot (forward), see how far you missed (loss), adjust your muscles (backward + step), repeat thousands of times.
import torch
import torch.nn as nn

class TitanicNet(nn.Module):
    def __init__(self, n_features):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(n_features, 16), nn.ReLU(),
            nn.Linear(16, 1), nn.Sigmoid())
    def forward(self, x):
        return self.net(x)

model = TitanicNet(X_train.shape[1])
loss_fn = nn.BCELoss()
opt = torch.optim.Adam(model.parameters(), lr=0.01)

for epoch in range(100):          # the training loop
    preds = model(X_train)          # forward
    loss = loss_fn(preds, y_train)  # how wrong?
    opt.zero_grad()                 # reset gradients
    loss.backward()                 # compute gradients
    opt.step()                      # update weights
Takeaway: On tiny tabular data a NN ≈ Random Forest. Deep learning shines on big, unstructured data (text, images).

11. Tokenization

Concept: LLMs don't read words — they read tokens (subword pieces). Common words = 1 token; rare words get split. This keeps the vocabulary small (~50k) while covering any text.
Analogy: Lego bricks — you don't need a unique brick for every object, you combine standard pieces.
import tiktoken
enc = tiktoken.get_encoding("cl100k_base")

tokens = enc.encode("ChatGPT is a LLM")
print("Count:", len(tokens))
for tid in tokens:
    print(tid, "->", repr(enc.decode([tid])))
# "ChatGPT" splits into multiple tokens; "is" is one.

12. Embeddings

Concept: Turn text into a vector of numbers where similar meaning = nearby vectors. Measure closeness with cosine similarity (1.0 = same meaning, 0.0 = unrelated).
Analogy: Map coordinates for meaning — two coffee shops sit close together; a coffee shop and an airport sit far apart.
from sentence_transformers import SentenceTransformer
from sklearn.metrics.pairwise import cosine_similarity

model = SentenceTransformer("all-MiniLM-L6-v2")
emb = model.encode([
    "The cat sat on the mat",
    "A dog rested on the rug",
    "Machine learning is fascinating",
])
print(cosine_similarity(emb).round(2))
# cat/dog sentences score high; ML sentence scores low.

13. Multi-turn Chat

Concept: A chat session remembers history by re-sending all previous turns with each new message. That's why it can answer follow-ups. A raw generate_content call has no memory.
client = genai.Client()
chat = client.chats.create(model="gemini-2.5-flash")

while True:
    user_input = input("You: ")
    if user_input.lower() == "quit":
        break
    response = chat.send_message(user_input)   # history auto-kept
    print("Gemini:", response.text)

14. RAG — Retrieval-Augmented Generation ⭐

Concept: LLMs don't know your data. RAG fixes this: retrieve the most relevant chunks from your documents, paste them into the prompt as context, and the LLM answers grounded in them. Kills hallucination and adds private knowledge.
Analogy: Open-book exam — don't memorize the textbook, just flip to the relevant page when a question comes.
from sentence_transformers import SentenceTransformer
from sklearn.metrics.pairwise import cosine_similarity
import numpy as np

docs = ["RAG combines search with LLMs.",
        "Transformers power modern LLMs.",
        "Embeddings map text to vectors."]

model = SentenceTransformer("all-MiniLM-L6-v2")
doc_emb = model.encode(docs)          # OFFLINE: embed once

def retrieve(question, top_k=2):
    q = model.encode([question])
    scores = cosine_similarity(q, doc_emb)[0]
    top = np.argsort(scores)[::-1][:top_k]   # highest first
    return [docs[i] for i in top]

# ONLINE: stuff retrieved context into the prompt
context = "\n".join(retrieve("What is RAG?"))
prompt = f"Answer using only this context:\n{context}\n\nQuestion: What is RAG?"
# ...then send `prompt` to Gemini -> grounded answer
Quiz: what's RAG's biggest weakness?

If retrieve() returns the wrong chunks, the answer is wrong. Garbage in → garbage out. The system is only as good as its retrieval.

15. Attention & Transformers theory

Concept: When processing each word, the model looks at all other words at once and weighs which matter. Each word emits a Query ("what I want"), a Key ("what I offer"), and a Value ("what I contain"). Query·Key = attention score; scores weight a sum of Values.
Analogy — dating app: your preferences (Query) matched against everyone's profile tags (Keys); best matches get most attention; you absorb the most from who you matched with (Values).
VectorRole
Query (Q)What this word is looking for
Key (K)What each word advertises — compared against Q
Value (V)The actual info — passed along as the weighted result

Why it changed everything: attention is computed in parallel for all words (not left-to-right), which is the only reason training on trillions of tokens became feasible. Multi-head = several attention "perspectives" at once (grammar, reference, etc.).

16. Encoder vs Decoder

EncoderDecoder (GPT/Gemini/Claude)
SeesWhole input, both directionsOnly tokens already generated (causal mask)
Good atUnderstanding (search, embeddings)Generating text, one token at a time
Exampleall-MiniLMChatGPT, Claude, Gemini
Key insight: Modern LLMs are decoder-only — pure next-token predictors. Causal masking hides future tokens during training so the model can't "cheat" by copying the answer; it's forced to genuinely predict. That one simple objective, at scale, produces grammar, facts, and reasoning.

18. Runtime Knobs

KnobWhat it controls
Context windowMax tokens the model can see at once (prompt + reply + history). Finite → the reason RAG exists.
TemperatureRandomness. Low (0–0.3) = focused/deterministic (facts, code). High (0.8+) = creative/varied (brainstorming).
top-k / top-pRestrict the pool of candidate next-tokens to the most likely ones — keeps output sane even when temperature is high.
Analogy — a chef: context window = how much of the recipe they remember; temperature = how adventurous; top-p = "only pick ingredients that make sense here."

20. RAG vs Agents

Concept: A plain LLM only outputs text. An agent can take actions — call tools, run code, query APIs — in a loop: Think → Act → Observe → repeat until the task is done. Each result decides the next step (which is why it needs a loop, not one pass).
Analogy: Plain LLM = brilliant person locked in a room answering from memory. RAG = slide relevant documents under the door first. Agent = give them a phone, internet, and calculator to look things up and act.
ApproachGives the model
RAGKnowledge (fresh, private data)
AgentCapabilities (the ability to act)

Fun fact: Claude Code (what taught you this) is an agent — it reads files and runs tools in a loop, not just chat.
